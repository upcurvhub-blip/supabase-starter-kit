## Goal

Make service edits appear immediately on public pages, give every public URL a distinct search description, and preserve both loaded data and scroll depth when visitors navigate back.

## Plan

### 1. Correct and enhance the public service detail page

- Read all enhanced service attributes from the saved `custom_fields` object instead of looking for them as top-level columns.
- Cleanly render highlights, visit charge, AMC availability, payment modes, GST invoice, advance percentage, experience, insurance, background verification, free site visit, working hours, certifications, warranty, response time, coverage, and team size only when present.
- Use a scannable service facts section that works for recurring software, professional services, maintenance, emergency work, and one-time services without empty labels.
- Add service-specific Open Graph URL/image, Twitter metadata, and Service JSON-LD with provider, area served, price/unit, and offer details.

### 2. Make seller edits refresh the public listing immediately

- After a service create, edit, activation change, or deletion, invalidate both the seller service list and every affected public service/detail/related-service query.
- Update the affected public detail cache directly after an edit where possible, then refetch in the background.
- Give entity-detail queries a shorter freshness policy than directory/list queries so persisted cache never hides a recent seller edit for ten minutes.
- Apply the equivalent invalidation to product edits so product detail metadata and fields cannot remain stale after seller changes.

### 3. Fix unique descriptions for crawlers

- Keep the existing unique product metadata path: product pages already generate product/seller/city-specific descriptions in React and the crawler renderer.
- Add `/service/:slug` to bot routing and implement service prerendering with a unique title, description, canonical, Open Graph tags, visible service content, provider link, and Service JSON-LD.
- Audit every public route in the router against the crawler renderer. Add route-specific metadata for uncovered static pages instead of allowing the homepage fallback description.
- Keep each canonical and `og:url` self-referencing on `https://upcurvtrade.upcurv.in`.
- Verify returned HTML using bot user agents for the homepage, a static page, a product, and a service. Google may continue showing an older cached snippet until it recrawls the URLs.

### 4. Replace the current cache/scroll behavior

- Replace unconditional route-change scroll reset with navigation-aware restoration: new link navigation starts at the top, while browser Back/Forward restores the exact saved scroll depth for that history entry.
- Save scroll positions before route changes and restore only after the destination content/layout is ready, preventing restoration to the wrong depth while data is still loading.
- Persist only explicitly public React Query data; exclude authenticated seller/admin/user queries from browser persistence.
- Preserve cached list results on back-navigation and use background refreshes without replacing the page with a loading state.
- Version the persisted cache format so the current stale cache is safely discarded once.

### 5. Validate the complete flows

- Edit the existing public service and confirm its enhanced fields and updated text appear immediately on its public URL.
- Navigate from a long product/category list into a detail page and Back, confirming both the list and exact scroll depth are restored.
- Check direct reloads and Back/Forward on desktop and mobile-sized viewports.
- Inspect rendered metadata and crawler HTML to confirm descriptions differ across static, product, and service URLs.

## Highest-impact next feature

Build a **Buyer RFQ Quote Comparison Inbox** next. Multi-seller broadcast already creates competition, but buyers still need one place to receive structured quotes, compare price/MOQ/delivery/payment terms, message suppliers, shortlist, and accept a quote. This closes the buyer loop that IndiaMART and TradeIndia rely on, increases repeat visits, and gives sellers a measurable quote-to-order funnel. The MVP can reuse the existing RFQ fan-out, lead assignments, seller lead inbox, WhatsApp contacts, and notifications; it should be a separate follow-up implementation after these reliability fixes.

- Normalize `service.custom_fields` once in the public component and render typed values from that normalized object.
- Use shared query-key helpers so seller mutations and public queries cannot drift apart again.
